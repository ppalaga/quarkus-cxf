# OIDC client implementation notes

_AI-generated by Codex on behalf of Peter Palaga._

## Dependency and policy decisions

The checkout uses Quarkus `4.0.0.Beta2`, rather than Beta1 described in the implementation plan.
Its `TokensHelper` supports a bounded cache keyed by additional grant parameters.
The extension delegates exchange reuse, expiry, refresh, and in-flight request sharing to that helper.
Each selected OIDC client has its own helper, and the parameters include the exact subject-token value.
Acquisition delegates to `AbstractTokensProducer`, including its early-acquisition and periodic-refresh integration.
Quarkus retains ownership of OIDC connections and refresh registrations until shutdown.

The implementation resolves the plan's policy questions as follows:

- Q-1: acquisition requires `grant.type=client`; RFC 8693 exchange requires `grant.type=exchange`.
  An absent selection uses the default client, and unknown or disabled clients fail at proxy creation.
  Selection is ignored in disabled and propagate modes.
- Q-3/Q-4: configured HTTP authentication conflicts and unsupported conduits fail at proxy creation.
  The extension does not replace the selected transport.
- Q-5/Q-9: lifecycle behavior comes from the Beta2 helpers.
  Caller-dependent exchange is lazy and has no contextless early acquisition or background refresh.
  Configured grant options belong to the selected OIDC client; there is no SOAP API for per-call option overrides.
  The endpoint request filter applies the selected `connection-timeout` to the HTTP response
  as well as connection setup.
  Beta2 otherwise sets only the connect timeout, leaving a delayed token response unbounded.
  Invalid successful responses are rejected before the helper can cache an absent or empty access token.
- Q-6: origin comparison normalizes default ports and compares scheme and host without case sensitivity.
  Credentials remain suppressed after a redirect leaves the initial origin, including a later return to it.
- Q-7: secure WSDL loading resolves authentication during proxy creation.
  Same-origin imports authenticate, and authenticated definitions bypass the shared WSDL definition cache.
  The conduit factory is scoped to the loading thread and passed through the document's endpoint properties,
  preserving CXF's conduit initialization without mutating the shared bus.
  The HTTP transport consults the same scope during factory lookup for CXF's separate XSD resolver.
  The shared bus's original extensions remain unchanged.
- Q-8: no refresh-on-unauthorized option is added.
  A failed SOAP operation is never automatically replayed for authentication.
- Q-10: an OIDC response filter sanitizes selected clients' failed responses before Quarkus logs or wraps them.
  Beta2's DEBUG request dump precedes request filters and does not mask `subject_token`.
  A chained logger filter redacts that dump before handlers receive it and restores the previous filter at shutdown.
  Actual bearer values are applied only to transport request options; CXF messages contain a masked placeholder.

## Corrections to the existing test setup

Existing integration-test assertions remain unchanged.
The following setup corrections are necessary to execute the specified scenarios:

- Remove the temporary explicit extension version now that the BOM manages the new artifacts.
  The repository's `EnforceManagedDepsRule` rejected that explicit version.
- Enable Quarkus `generate-code` and `generate-code-tests` goals.
  Without them, the generated SOAP interfaces required by T-002 through T-004 were absent and compilation failed.
- Set the fixture's OIDC connection retry counts to `1`.
  Beta2 `OidcClientImpl.preparePostRequest()` calls Mutiny `retry().atMost(count)`, which rejects `0`
  before sending any token request, making every positive acquisition/exchange scenario fail.
  T-014 requires finite settings and explicitly does not prescribe a retry count.
- Enable the file log sink consumed by T-018's `TestLog` and token-provider DEBUG diagnostics.
  Previously, both logging tests timed out waiting for a file that was never enabled,
  so they could not exercise T-018's required active-log and secret-absence assertions.
- Correct T-019's cold-WSDL setup to remove all cached identity aliases of the document.
  Runtime tracing showed `removeDefinition(String)` returning while the same manager still contained the URL.
  CXF 4.2.4's `CacheMap.remove()` collapses equal identity keys into a `HashSet` before removing them,
  and the string overload introduces another alias during lookup.
  The fixture now uses the definition overload without introducing aliases and repeats until the URL is absent.
  Normal public-WSDL caching remains unchanged in production.
- Move the T-007 invalid-mode augmentation test to the new extension's deployment test module.
  Beta2 rejects mixing `QuarkusExtensionTest` and `QuarkusTest` in one test run before executing the test.
  The invalid-mode assertion and scenario tag are preserved;
  its archive uses the extension test's simple SOAP interface.

Run the local-fixture tests with `-Dquarkus.keycloak.devservices.enabled=false`.
Their authentication-server URLs are supplied by test resources after the Dev Services startup phase.
This avoids starting an unrelated Keycloak container for these tests.
The original `HelloServiceTest` still requires Keycloak and is separate from the outbound OIDC fixture suite.
